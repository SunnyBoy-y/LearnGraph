# 全站备份与恢复

设置 → 数据与存储 → 全站备份与恢复。只有系统管理员可下载、校验和暂存全站备份；普通成员和工作区管理员均无权操作。每次操作在服务端验证当前管理员密码，失败限流；旧 GET 下载接口已经关闭。

下载时设置独立备份密码（至少 12 位）。整个内容使用 scrypt 派生密钥和 Fernet 认证加密，ZIP 里只可见加密格式说明与密文；API Key 不会以明文出现在可直接解压的文件里。请单独保存备份密码，丢失后无法恢复。

备份内容：

- SQLite 在线一致性快照：全站所有用户、工作区、权限、业务记录、模型配置和凭据、二进制字段、历史配置均完整保存。
- 默认本地 storage 和 memory 下所有文件，包括 Memory 恢复密钥；数据库引用的上传文件逐个验证大小与 SHA-256。
- 实际生效的 Settings、全部 LEARNGRAPH_ 环境变量、启动目录的 .env 原文（如存在）、已配置的桥接／sandboxd／更新令牌文件。
- 持久化的沙箱镜像选择、初始化策略、镜像源与预览配置。
- 使用 OS Keyring 时保存当前及历史版本主密钥和可用的 identity key，恢复到独立 Keyring 命名空间。

当前仅支持本地 SQLite 和默认本地对象存储。外部数据库、活动 MinIO 或自定义存储根目录会明确拒绝，避免生成不完整的全站包。外部服务、运行中的沙箱磁盘、源码和容器镜像需要各自的备份。数据库快照是事务一致的；文件目录无法与数据库跨介质原子冻结，建议先停止任务和写入再下载。文件丢失、校验失败、链接逃逸或超限都会报错。

恢复流程：

1. 管理员上传加密 ZIP，输入当前管理员密码和备份密码。服务端解密，校验 ZIP 路径、去重、解压总量、清单、SHA-256、数据库完整性和外键，成功后只暂存原始密文。
2. 停止所有 API 实例、worker、定时任务及其他数据库写入方。在 backend 目录、原部署相同的 Python 环境执行页面给出的命令：

   ```text
   python -m app.services.site_restore --backup "页面显示的路径.zip" --server-stopped
   ```

3. 工具以隐藏输入读取备份密码；全站数据库和两个受管目录会被覆盖，数据库路径及 storage/memory 目标沿用当前实例位置。有效配置写入当前目录 .env。使用 `--env-file` 可指定目标配置文件。原数据库、目录、配置的恢复前副本保留在同级 `*.before-site-restore-*` 中；应用失败会尝试回滚。
4. 启动／容器的环境变量优先于 .env。工具检测到冲突会在改动数据前拒绝执行，并只列出变量名；需先同步部署配置、从无冲突的终端重试。配置中的外部服务地址和令牌文件路径需要在目标主机上仍然可用。重启并使用备份中的账户重新登录，旧登录会话已撤销。

`--server-stopped` 是操作者对已停服的确认，不会自动关闭其他进程。不要在生产运行中执行覆盖恢复。恢复前副本也包含敏感信息，应由管理员保管。页面“校验并暂存”不代表全站数据已恢复。

默认上限为 LEARNGRAPH_MAX_BACKUP_BYTES（1 GiB），同时限制密文、解压总量和成员数量；当前实现会在内存中生成与验证包，较大站点应使用离线存储／数据库原生灾备。移动端大于原生保存桥容量的包应在桌面浏览器下载。旧的脱敏工作区 ZIP 不兼容全站恢复，解析器会明确拒绝。
