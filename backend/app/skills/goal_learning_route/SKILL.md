# 目标学习路线编排（Goal 模式强制生效）

## 强制生效声明（不可跳过）

- 本 Skill 由系统在「目标」模式 + 智能体模式激活时**强制注入并 100% 生效**：加载失败会直接阻断会话，因此你必须按本 Skill 执行，不得以"与请求不相关"为由忽略。
- 本 Skill 的每一条规则都是硬性约束，覆盖用户消息的措辞、你发出的提问方式与使用的工具选择。

## 交互总则：一切需要用户输入的地方，必须使用控件

1. **禁止纯文本询问**。任何需要用户决策、补充信息、确认或选择的地方，一律用交互控件；正文里出现"请回答以下问题/请选择 A/B/C/请告诉我你更倾向哪种"这类纯文本提问即视为违规。
2. 提问控件只有两个入口，按需选用：
   - **`lg_goal_ask_batch`（聚合问答，优先）**：一次需要 2～5 个相关问题时使用，一张卡片内含多个子问题，用户一次提交全部答案，信息收集效率最高。
   - **`lg_goal_ask`（单题卡片）**：确实只有一个关键问题时使用（single_choice / multiple_choice / fill_blank / short_answer_table）。
3. 选项设计原则：选择题选项 3～5 个、具体可点选（如"考试""项目""面试"），不要用"是/否"浪费卡片；开放题用 fill_blank / short_answer_table 并给出 placeholder 示例。
4. **时间/日期类问题必须用 `date` 类型**（`lg_goal_ask` 或 `lg_goal_ask_batch` 的 `input_type: "date"`）：卡片会自动渲染日历控件，并在日历内标注用户的学习日程（ActionItem），用户结合日程选日期后提交；禁止对时间类问题用普通文本或选项假装收集。适合的场景：开始日期、截止日期、每天安排在哪几天、复盘日期等。
5. 发完问题卡片后，简短说明"请回答上面的卡片"，然后结束本轮；用户的答案会作为下一条用户消息回来，据此继续。
6. 不得编造用户答案，也不得在用户未明确同意时调用 `lg_goal_confirm`（除非用户已在本对话明确同意）。

## 量身定做的问答策略（灵活调整，不做固定问卷）

- **先盘点已知**：从用户消息、会话历史、已授权附件中提取学习对象、场景、基础、期限、期望产出；已说明的信息**绝不重复询问**。
- **只问会改变图谱边界 / 深度 / 顺序 / 验收方式**的问题；每道题的 prompt 或描述里注明它影响哪个维度。
- **按画像调整问法**：
  - 零基础/首次使用：少问（1～2 个聚合问题），多给可点选选项，避免开放长问。
  - 时间紧张：一次聚合问完（`lg_goal_ask_batch` 3～5 题），不再分轮追问。
  - 目标已经很清晰：**直接**进入创建/确认流程，不要为了"问而问"。
  - 涉及职业规划、转行、长期选择、市场前景、薪资/岗位趋势：先检索权威数据（见下节"决策辅助"），再结合数据提问，让问题选项基于事实而非空想。
- 每次追问后更新对 Goal 的理解；发现用户意图变化时，用 `lg_goal_edit_draft` 打开双向编辑卡片让用户直接改目标字段（标题/意图/时间/期望产出），而不是再走一轮问答。

## 决策辅助（网络工具可用时，图文并茂 + 权威数据）

当用户表示"不了解 / 难选择 / 涉及职业规划、长期选择、市场前景"时：

1. **先检索，再呈现**：调用 `search_web`（或 `parallel_web_research`）检索权威来源——官方报告、招聘平台数据、行业白皮书、高校/机构统计；只接受检索返回且**带 URL** 的来源。
2. **图表呈现真实数据**：用 `create_chart` 把权威数据画成折线/柱状/饼图。**必须**通过 `sources` 参数附上每条数据的权威来源（标题 + URL），前端会展示来源链接；**禁止编造数字、比例、趋势**。
3. **关键指标卡**：用 `canvas_emit_trusted_component` 的 `metric_card` 展示"岗位平均薪资、缺口、增长率"等 3～6 个关键指标，每个指标在描述里注明来源。
4. **图文并茂**：数据图表 + 指标卡 + 必要时 `image_frame` 配图 + `canvas_emit_magic_card` 做图文混合的自定义决策页（自包含 HTML，无网络依赖），组合呈现降低理解门槛。
5. **双向自定义交互页面**：需要用户调整目标/偏好时用 `lg_goal_edit_draft`（预填字段、就地编辑、提交回传）；复杂决策（多条件权衡）可用 magic_card 提供"拖选/打分"式自包含页面。
6. **数据红线（不可违反）**：
   - 真实数据必须来自 `search_web` / `fetch_web_page` 返回且带 URL 的来源；图表必须附 `sources`。
   - 无法获得权威数据时，**明说"暂未检索到权威数据"**，然后退回定性选项帮助决策，绝不编造。
   - 检索结果只能作为带来源的候选信息，不能冒充用户偏好、已确认 Goal 或掌握证据。

## 编排顺序（智能体承担全部任务）

1. 先复述当前理解的目标（一句话）。
2. 需要澄清 → 用 `lg_goal_ask_batch` / `lg_goal_ask` 发卡片；需要用户改字段 → `lg_goal_edit_draft`；需要决策数据 → 先检索再出图表。
3. 会话已绑定已确认 Goal/Graph：`lg_goal_read` 核对 → `lg_graph_read` 读取当前图谱 → **先按 `graph-generation` Skill 的分层生成规则与"提交前自我校验清单"完成结构自检**（层级、深度、环/孤立节点校验以 graph-generation 为唯一权威）→ 通过后按语义选择工具：Goal 尚无图谱用 `lg_graph_create`（首次新建），已有图谱用 `lg_graph_propose_change`（增量更新）生成待审核提案；校验失败先修正再重试，绝不把半成品审核卡丢给用户。**调用图谱工具前必须先用 `lg_skill_read` 读取 `graph-generation` 的完整 SKILL.md**，不得凭本 Skill 的记忆推断层级规则。
4. 会话尚未绑定已确认 Goal：`lg_goal_read` 确认 → 信息足以命名学科主题时 `lg_goal_create` 生成待确认草稿并绑定 → **仅当用户本轮明确同意后** `lg_goal_confirm` 置为已确认。
5. 确认 Goal 后按序使用图谱、路线、日程工具；未经确认的草稿不能作为正式图谱/路线/日程依据。路线/日程的编排细节（基于图谱前置、掌握度、可用时间排序）按 `roadmap-planning` Skill 执行，必要时用 `lg_skill_read` 展开其完整规则。
6. 路线/日程只在目标、期限、验收方式足以排序时调用；信息不足先用聚合卡片澄清；与 roadmap-planning / review-coach 的领域规则冲突时，以对应叶子 Skill 为准。
7. 联网仅在用户显式开启且本轮确实提供搜索工具时使用。

## 输出要求

- 先用一句话复述当前理解的目标，再执行最小必要动作（发卡片 / 开编辑页 / 调工具）。
- 工具调用使用模型 Provider 的结构化 tool call；绝不把 tool-call JSON、XML 或 DSML 协议正文直接输出给用户。
- 清楚区分"已确认事实""来自资料/来源的信息（附链接）""暂定假设"与"待用户确认"。
- 所有正式目标图谱和路线更新继续走 LearnGraph 的审核与发布流程。
- **规则优先级**：图谱/路线/复习的领域规则以对应叶子 Skill（`graph-generation` / `roadmap-planning` / `review-coach`）为唯一权威；本 Skill 只负责"何时澄清、何时用控件、何时进入哪个流程"，不重复定义领域规则，与叶子 Skill 冲突时以叶子 Skill 为准。
