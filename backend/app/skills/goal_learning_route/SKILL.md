# 目标学习路线编排

## 何时使用

- 仅当本轮同时处于 Goal 模式和智能体模式时使用。
- 用户希望从普通对话中描述学习目标、补充资料，并逐步形成可审核的学习结构或路线。

## 决策顺序

1. 先从用户消息、当前会话上下文和已明确授权的附件中提取：学习对象、使用场景、现有基础、期限/可用时间、期望产出与约束。
2. 只追问会改变图谱边界、深度、顺序或验收方式的缺失信息。一次优先询问 1～3 个关键问题；不得用固定问卷重复询问用户已说明的信息。
3. 如果本轮实际提供了文件或沙箱工具，并且用户明确附加或引用了资料，可以调用它们核对资料结构；未提供对应工具时要说明能力不可用，不得编造读取结果。
4. 如果会话已经绑定已确认的 Goal/Graph，且本轮实际提供图谱工具，先 `lg_goal_read` 核对绑定状态，再 `lg_graph_read` 读取当前图谱并自我校验（无重复概念、无孤立节点、无层级混乱、无前置/contains 环、更新使用真实 node_id；首次生成仅 0+1 层，拆分只在已有节点下一层），通过后才调用 `lg_graph_propose_change` 生成待审核提案。该工具不得被描述为已经发布正式图谱；校验失败应修正后重试，不要把半成品审核卡丢给用户。
5. 如果会话尚未绑定已确认 Goal：先调用 `lg_goal_read` 确认当前没有 Goal；从用户消息和会话历史上下文中挖掘学习需求、使用场景、现有基础与期望产出，信息足以命名学科主题时调用 `lg_goal_create` 生成待确认的 Goal 草稿并绑定到当前会话；只有用户在本轮对话中明确同意该 Goal 后，才调用 `lg_goal_confirm` 将其置为已确认。不得通过猜测补齐用户未说明的期限、可用时间或期望产出，也不得在缺少用户确认时调用 `lg_goal_confirm`。
6. 绑定并确认 Goal 后，图谱、路线、日程工具才可依次使用；未经确认的 Goal 草稿不能作为正式图谱、路线或日程的依据。
7. 只有在目标、期限/可用时间和验收方式足以支持排序时，才建议或调用路线工具。信息不足时先澄清，信息充分时再形成路线草稿。
8. 联网只在用户显式开启且本轮确实提供搜索工具时使用；搜索结果只能作为带来源的候选信息，不能冒充用户偏好、已确认 Goal 或掌握证据。

## 输出要求

- 先用一句话复述当前理解的目标。
- 然后执行最小必要动作：提问，或调用一个最相关的已授权工具。
- 工具调用使用模型 Provider 的结构化 tool call；绝不把 tool-call JSON、XML 或 DSML 协议正文直接输出给用户。
- 清楚区分“已确认事实”“从资料/来源获得的信息”“暂定假设”和“待用户确认”。
- 所有正式目标图谱和路线更新继续走 LearnGraph 的审核与发布流程。
