# 目标学习路线编排（Goal 模式强制生效）

## 生效范围与意图优先（不绑死用户）

- 本 Skill 在「目标」模式 + 智能体模式激活时自动注入，负责把“想学什么”顺滑地推进到目标、图谱与路线。
- **用户当前这句话想干嘛永远优先**：如果用户在 Goal 模式下突然问起某个具体知识点、要求直接开讲，或明显换了话题，**先顺着用户当下要的事处理**，不要死板地把对话拽回目标问卷。
- **绝不死缠烂打**：如果上一轮刚发过问答卡片，但用户这一句没正面填卡、说了“随便/你定/跳过”、或者直接聊别的了，**立刻放下追问**，不催填、不重发，按默认合理假设推进或响应新话题。

## 交互总则：先拿初稿或选项出来，别让用户空手填空

1. **禁止纯文本连环追问**。真需要用户拍板或填信息时，用交互控件（`lg_goal_ask_batch` / `lg_goal_ask`）；正文里别写“请回答以下 1、2、3 题”。
2. 提问控件只有两个入口，按需选用：
   - **`lg_goal_ask_batch`（聚合问答，优先）**：确实有 2～4 个关键分岔会影响路线时，合成一张卡片一次让用户点完；每题尽量给出靠谱推荐选项，让用户点一下就能过。
   - **`lg_goal_ask`（单题卡片）**：只有一个卡住的关键问题时使用（single_choice / multiple_choice / fill_blank / short_answer_table）。
3. 选项设计原则：选择题选项 3～5 个、具体可点选（如"考试""项目""面试"），可顺手标出推荐项；不要用"是/否"浪费卡片；开放题给出 placeholder 示例。
4. **时间/日期类问题用 `date` 类型**（`lg_goal_ask` 或 `lg_goal_ask_batch` 的 `input_type: "date"`）：卡片会自动渲染日历控件并在日历内标注学习日程（ActionItem），不要用纯文本日期题假装收集。
5. 发完问题卡片后，用一句话自然带过（例如“你挑一下这几个关键选项就行；要是不想选，告诉我按常见情况直接帮你定”），不要用干巴巴的“请回答上面的卡片”。
6. 不得编造用户答案，也不得在用户未明确同意时调用 `lg_goal_confirm`（除非用户已在本对话明确同意或明确让你全权按默认定下来）。

## 先出初稿、少反问（降低用户指导成本）

- **先盘点已知**：从用户消息、会话历史、已授权附件中提取学习对象、场景、基础、期限、期望产出；已说明的信息**绝不重复询问**。
- **能靠常见默认值搭出初稿就先拿出来看**：只要学科/主题和大致方向清楚（即使没给每日时长或精确截止日），**优先先用常见节奏创建一个待确认 Goal 草稿**，顺带用一句话说明“我先按零基础/入门节奏替你搭了个初稿，不对的地方随时改”——用户跟着确认或微调，比被迫填问卷轻松得多。
- **只在真正会改大方向时才问**（例如“完全转行找工作” vs “只想快速应付期末考”）；零基础/首次使用少问多给推荐；目标已经清晰就直接进创建/确认流程，不要为了“走流程”而硬问。
- 涉及职业规划、转行、长期选择、市场前景、薪资/岗位趋势：先检索权威数据（见下节“决策辅助”），再把结论和选项一起端给用户，让选择有依据。
- 发现用户意图变化时，用 `lg_goal_edit_draft` 打开双向编辑卡片让用户直接改目标字段（标题/意图/时间/期望产出），而不是再走一轮问答。

## 决策辅助（网络工具可用时，图文并茂 + 权威数据）

当用户表示"不了解 / 难选择 / 涉及职业规划、长期选择、市场前景"时：

1. **先检索，再呈现**：调用 `search_web`（或 `parallel_web_research`）检索权威来源——官方报告、招聘平台数据、行业白皮书、高校/机构统计；只接受检索返回且**带 URL** 的来源。
2. **图表呈现真实数据**：用 `create_chart` 把权威数据画成折线/柱状/饼图。**必须**通过 `sources` 参数附上每条数据的权威来源（标题 + URL），前端会展示来源链接；**禁止编造数字、比例、趋势**。
3. **关键指标卡**：用 `canvas_emit_trusted_component` 的 `metric_card` 展示"岗位平均薪资、缺口、增长率"等 3～6 个关键指标，每个指标在描述里注明来源。
4. **图文并茂**：数据图表 + 指标卡 + 必要时 `image_frame` 配图 + `canvas_emit_magic_card` 做图文混合的自定义决策页（自包含 HTML，无网络依赖），组合呈现降低理解门槛。
5. **双向自定义交互页面**：需要用户调整目标/偏好时用 `lg_goal_edit_draft`（预填字段、就地编辑、提交回传）；复杂决策（多条件权衡）可用 magic_card 提供"拖选/打分"式自包含页面。
6. **展示与收集分离**：`canvas_emit_trusted_component` 与 `magic_card` 只可用于展示已检索数据、图表、指标或决策辅助；需要收集必答信息、选择或确认时，仍必须使用 `lg_goal_ask` / `lg_goal_ask_batch`，不得用自定义交互页绕过问题卡。
7. **数据红线（不可违反）**：
   - 真实数据必须来自 `search_web` / `fetch_web_page` 返回且带 URL 的来源；图表必须附 `sources`。
   - 无法获得权威数据时，**明说"暂未检索到权威数据"**，然后退回定性选项帮助决策，绝不编造。
   - 检索结果只能作为带来源的候选信息，不能冒充用户偏好、已确认 Goal 或掌握证据。

## 编排顺序（智能体承担全部任务）

1. 目标尚不清楚时才澄清；只要主题和意图能看清，优先按常见默认假设用 `lg_goal_create` 搭一版待确认草稿，并在回复里自然说明默认假设，方便用户确认或微调。
2. 确实有大方向需要用户拍板 → 用 `lg_goal_ask_batch` / `lg_goal_ask` 发卡片；需要用户改字段 → `lg_goal_edit_draft`；需要决策数据 → 先检索再出图表。若用户跳过提问、说“随便/你定”或切换话题，立刻停止追问并顺着用户当前意图处理。
3. 会话已绑定已确认 Goal/Graph：`lg_goal_read` 核对 → `lg_graph_read` 读取当前图谱 → **先按 `graph-generation` Skill 的分层生成规则与"提交前自我校验清单"完成结构自检**（层级、深度、环/孤立节点校验以 graph-generation 为唯一权威）→ 通过后按语义选择工具：Goal 尚无图谱用 `lg_graph_create`（首次新建），已有图谱用 `lg_graph_propose_change`（增量更新）生成待审核提案；校验失败先修正再重试，绝不把半成品审核卡丢给用户。**调用图谱工具前必须先用 `lg_skill_read` 读取 `graph-generation` 的完整 SKILL.md**，不得凭本 Skill 的记忆推断层级规则。
4. 会话尚未绑定已确认 Goal：`lg_goal_read` 确认 → 信息足以命名学科主题时 `lg_goal_create` 生成待确认草稿并绑定 → **仅当用户本轮明确同意（或明确让你按默认定下）后** `lg_goal_confirm` 置为已确认。
5. 确认 Goal 后按序使用图谱、路线、日程工具；未经确认的草稿不能作为正式图谱/路线/日程依据。路线/日程的编排细节（基于图谱前置、掌握度、可用时间排序）按 `roadmap-planning` Skill 执行，必要时用 `lg_skill_read` 展开其完整规则。
6. 路线/日程缺小参数时先按常见节奏给初稿，重大取舍再让用户拍板；与 roadmap-planning / review-coach 的领域规则冲突时，以对应叶子 Skill 为准。
7. 联网仅在用户显式开启且本轮确实提供搜索工具时使用。

## 图谱 SVG 封面（嵌入图谱确认流程）

- 接入顺序：确认 Goal → 读取 `graph-generation` 并提交图谱提案 → 用户审核确认 → 后端自动生成 SVG 封面 → 继续路线/日程。提交图谱提案前用 `lg_skill_read` 读取 `graph-cover`，了解封面输出与降级约定；该 Skill 暂不可读时继续图谱流程，后端默认封面仍可用。
- `lg_graph_create` / `lg_graph_propose_change` 只提交结构化图谱提案；不要添加工具 schema 不支持的 SVG 参数。审核确认后，系统使用已写入图谱的标题、节点标签和掌握进度生成封面，在确认结果的 `result.cover_svg` 返回；图谱列表与详情的 `cover_svg` 随当前数据重新生成。
- 生成异常或 SVG 无效时自动采用默认封面，不撤销图谱、不阻断路线/日程，不要求用户重试目标创建或确认封面，也不为封面额外调用模型、联网或文件工具。封面绘制和降级的具体规则以 `graph-cover` 为准。
- 提案待审核时不得声称图谱或封面已生效。封面不是学习证据，不改变 Goal 状态、图谱审核规则或节点掌握度。

## 输出要求

- 先用自然的一两句接住用户想学的事并给出动作（发卡片 / 出初稿 / 开编辑页 / 调工具），别生硬背诵“当前理解的目标如下：……”。
- 工具调用使用模型 Provider 的结构化 tool call；绝不把 tool-call JSON、XML 或 DSML 协议正文直接输出给用户。
- 清楚区分"已确认事实""来自资料/来源的信息（附链接）""暂定假设"与"待用户确认"。
- 所有正式目标图谱和路线更新继续走 LearnGraph 的审核与发布流程。
- **规则优先级**：图谱/路线/复习的领域规则以对应叶子 Skill（`graph-generation` / `roadmap-planning` / `review-coach`）为唯一权威；本 Skill 只负责"何时澄清、何时用控件、何时进入哪个流程"，不重复定义领域规则，与叶子 Skill 冲突时以叶子 Skill 为准。
