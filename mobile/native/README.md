# LearnGraph Android 0.18.4

应用默认进入 Kotlin / Jetpack Compose 的登录、聊天与会话侧栏。输入、流式传输、本地缓存、重试、停止、队列、滚动与抽屉由原生处理；消息和右侧图谱使用打包在 APK 内的现有 Web 组件，由安卓系统 WebView 渲染。主聊天以现有 WebUI 手机端为基准。

UI 依据 `frontend/src/index.css` 的最终级联和 `chat-pages.tsx` / `use-conversation-scroll-controller.ts`：悬浮导航及模型胶囊、左对齐空态、12dp 内容边距、80% 用户气泡、20dp 输入框、目标/联网工具条、40dp 输入动作、深浅主题、抽屉 320ms 指定曲线与阅读锚。`answer.started` 保留最终正文边界与冻结思考时间，思考与工具过程共用一条过程链；文本与思考增量分别按约 50ms / 16ms 合批显示。

53 个图标直接从当前 `lucide-react` 几何路径生成，语音图标取 Web 自定义波形；Geist 拉丁字体直接从 Web 字体生成 API 23 可用的静态字体。左侧抽屉 320ms、右侧 340ms、透明度和遮罩 180ms；方向锁为 8dp / 1.2，超过半程吸附，不额外使用 fling 判定。输入、选文、表格、横向滚动与画布保留手势所有权。模型滑条复用 Web 的尺寸、离散档位和跨档震动时机。

原生与 Web 共用震动开关和波形：最终回答开始后的 14ms / 150ms 连续震动、工具完成 900ms 节流、成功完成庆祝；终态、异常、取消、失焦和后台停止，不回放历史事件。深浅色使用 Web 的显式主题，按账号/工作区缓存；Home 统一刷新设置，网页切换主题同步回原生。

CSS px 按 Android dp 对齐，文字使用 sp。0.18.4 在 vivo V2339FA / Android 16、360×800dp、系统字号 1.0 上继续同机对照。基线采用 Android Blink 的主字体取整、26.6 LayoutUnit 与半行距分配规则；实际中文标题由 74.49 修正为 73 个物理像素，与同机 Web DOM 测得值一致。模型菜单的行高、圆角、外描边、CSS 阴影与缩放原点按最终级联校正；Popup / Dialog 等真实窗口布局完成后才启动入场动画。搜索保留外点关闭、内部空白保护和键盘收起，并按 Web 的条件卸载即时关闭；初开与切换范围立即请求，仅输入文字防抖 250ms。系统震动仍受厂商波形映射影响；单台设备的参数、日志和录屏不足以证明所有页面、机型、系统字号和输入法达到 100% 像素或触感一致。

本轮已完成同账号、同工作区、同会话的双向发送实测：Web 发送后 Native 自动显示，Native 发送后 Web 自动显示，无需刷新；回答后的推荐问题也复用原 Web 组件和同一持久批次。实际同步记录包含更新后的 200 与无正文的 304。141 项安卓单元测试、93 项定向前端测试、5 项条件请求后端测试及 TypeScript 检查通过；952 个本地资源哈希与签名校验通过。arm64 包 24.75 MiB，通用包 38.17 MiB；下载完整文件、Range 与最终安装包哈希核对记录见 `../../logs/native-v0184-acceptance.json`。此前 0.18.3 的历史过程折叠、模型搜索、草稿交接、系统附件选择等验收证据保留在 `../../logs/native-v0183-detail-acceptance.json`。

## 保留的能力与迁移边界

消息正文复用 `AnswerParts` / `ChatStreamPartRenderer`、Streamdown、KaTeX、Mermaid、图表、引用、图片、测验分页、注册的声明式组件和沙箱组件。整个过程区复用 `ThinkingChain` 和 `ReasoningSummaryRow`，包括历史默认折叠、内部完整过程展开、回答边界的一次收起及原动画；流结束的首次版本归一化保留同一个 WebView。默认折叠设置成功保存后按当前身份即时回写原生。生成提示直接复用 `StreamStatsBadge`。不再将已知复杂消息类型统一降级成摘要卡片或强制跳完整网页。图谱抽屉复用原 `ContextRail`。完整设置、文档学习、资料、产物、语音等页面沿用原业务页面与权限桥；这些页面与消息入口共用 APK 内同一份组件资源和依赖块，API 仍请求所选服务器；支持所有同工作区页面路径，保留 query/hash。

原生侧栏支持项目与会话改名、置顶、归档、恢复、移动、项目内新会话、批量删除影响确认，以及完整对话/消息区间/仅回答分享和撤销链接。全工作区搜索沿用原 API，支持文件、会话、消息正文与 ID；消息结果交给原 Web 的历史分页定位逻辑。消息外层接入复制、消息 ID、编辑新分支、回答快照版本和用户分支版本导航；重试设置仅本次生效并保留历史版本。

附件、拍照、目标、绘图与语音入口通过本地单次动作触发原 Web 控件；输入草稿不写入 URL。返回前读取 Web 输入框当前值，未发送内容交回原生，已发送的空值同步清除原草稿。进入下载管理也先交回草稿，关闭下载管理后返回原生会话。模式、思考力度、模型、联网和绘图设置通过有版本及身份范围的公开状态合约双向同步，包含尚未发送的新会话；只有前端确认应用成功的请求才接受全量返回设置，超时保留原生选择。

组件动作保留普通回答、问答批次、草稿编辑、图谱审核、先校验 revision 的 UI 动作、训练器分析、图谱更新和节点上下文；交互参数通过原生白名单校验并随队列保留。弹窗/图片预览将同一个 WebView 移入全屏宿主，避免短消息高度改变弹层视口或重新挂载丢失表单状态。下载接受相对 URL，导出上限与 Web 的 20 MiB Blob 契约一致。

没有打包 Chromium、GeckoView、Crosswalk 或其他浏览器内核。共享组件代码、字体和完整业务前端直接从 APK 本地读取，不依赖服务器部署新的 renderer 路由或新的设置交接合约。只有当前工作区的 SPA 主文档替换为本地入口，API、下载与外部地址保持原请求路径。代码训练器的大型解释器按需从当前服务器的 `/code-trainer/` 获取。

拍照、分享收件箱、文件选择、下载、网页麦克风权限、通知、小组件、快捷方式和指纹门禁沿用现有 Android 集成。复杂快捷动作会交给原有网页桥接处理。保留入口并不代表所有这些业务界面都已改写成 Compose；真机上的语音、相机、分享和通知还需要设备验收。

## 缓存与同步

- 先读取应用私有目录 `noBackupFilesDir/native-cache-v1` 的记录，再更新网络数据。缓存不会随 Android 云备份上传。缓存按服务器地址、账号与工作区隔离，退出登录清除当前账号缓存。
- 会话列表缓存有效期 30 秒，最近消息页 10 秒；手动刷新绕过有效期，仍发送条件请求。无变化时服务端以 `ETag / If-None-Match` 返回无正文的 304。
- 项目分组与元数据也保存在同一私有磁盘缓存中，30 秒有效期；项目创建、改名、归档和删除会更新缓存，旧列表请求不会覆盖已经确认的修改。项目服务未返回 `ETag` 时，过期更新仍会重传项目元数据。
- 侧栏账号名、工作区名和服务器版本按身份保存在私有缓存，60 秒有效期，打开侧栏时按需更新；请求失败保留同身份缓存，身份切换取消旧请求并阻止迟到响应写入新界面。
- 首次打开只下载最近 50 条消息。更早记录由“加载较早消息”按钮分页请求；同步时重新校验已展开页，并保护版本与分页游标，避免删除、重试或切换分支后的旧内容残留。
- Native 和 Web 在可见且没有本地生成时，每 2 秒加请求耗时静默检查当前会话。发现另一端生成后沿现有事件链路跟随；本地 SSE 期间不让旧快照覆盖增量，结束后再协调。304 不触发重绘、滚动、震动或加载提示；后台停止跟随，回前台重新校验。该间隔不代表跨端逐字零延迟。
- 侧栏的最后活动时间、已读完成标记、当前运行和语音状态使用有身份及页面所有者范围的状态合约；页面退出释放其临时运行状态，持久时间与未读标记保留，避免旧页面迟到事件污染其他账号。
- 条件请求需要部署本次更新的后端。旧服务器仍能使用本地缓存和分页，但不会返回 304。内容变化时重传会话摘要或最近消息页；这不是逐条变更日志的 delta-sync 协议。服务端仍需查询并校验响应内容。
- 缓存总量上限 32 MiB，单项上限 8 MiB，超过上限的内容仍可在线显示但不会全部离线保留。较早分页和复杂网页资源不保证离线可用。
- 网络异常保留已缓存的消息与输入草稿；离线可阅读缓存，生成回复仍需连接服务器和模型服务。会话删除、失去访问权限和工作区切换均重新校验。
- 响应模式、思考力度、联网和模型选择映射到现有消息创建接口；已选会话的设置也缓存在同一账号作用域。模型目录在进入身份后加载，同身份 30 秒内复用；有效模型按 Web 的本地偏好、会话快照和供应商原顺序解析，菜单标记与实际发送使用同一组 ID。本地设置尚未恢复或目录尚未就绪时保留草稿，避免发到另一默认模型。

## 构建

安装 JDK 21、Android SDK `platforms;android-35` 和 `build-tools;35.0.0`，通过 `JAVA_HOME` 与本机 `local.properties` 配置环境。先在 `frontend` 执行 `npm ci` 安装共享渲染器依赖。

在 `mobile` 目录执行：

```text
npm run test:native
npm run apk:debug
npm run apk:compact
```

三个 APK 命令都会先构建共享组件。直接调用 Gradle 前需在仓库根目录运行 `node mobile/scripts/build-native-renderer.mjs`；缺少消息入口、完整应用入口或资源 manifest 时打包任务会失败。生成的 renderer 资源不入 Git，图标/字体源、许可证和生成校验脚本保留在 `tools/` 与 `app/src/main/assets/licenses/`。

`apk:compact` 开启 R8 与资源压缩，使用本机 debug key 签名，便于本地安装。正式发布使用 `apk:release` 并配置自己的发布密钥，不能将测试签名当作生产发布签名。`apk:legacy` 显式构建早期 Capacitor 壳。

产物在 `app/build/outputs/apk/compact/`：普通现代手机通常使用 `arm64-v8a`，兼容未知架构可用 `universal`。同时保留 `armeabi-v7a`、`x86`、`x86_64` 包。扫码库的原生文件会按架构拆分，避免每台手机携带四套文件。包的实际大小以构建产物为准。

UI 对照预览在 `../../docs/previews/native-mobile-before-after.html`，是依据代码绘制的交互预览，并非安卓设备截图。
共享组件的真实生产渲染预览：`frontend` 目录执行 `npx vite preview --config vite.native-renderer.config.ts` 后打开 `/__lg_renderer_v1/native-renderer.html`。这里运行 APK 打包的相同组件代码，仍不代表 Android 真机验收。
