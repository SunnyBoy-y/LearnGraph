## 最终结论：**NO_GO**

当前工作树形态（拟发布版本）**不具备上线条件**，原因按优先级：

1. **P0-1 生产构建崩溃**（阻断项）：构建产物模块求值阶段抛 `TypeError: s is not a function`，全部页面白屏；HEAD 干净构建正常，回归由工作树未提交修改引入。**该问题修复并验证前，一切上线讨论无意义。**
2. **S1-1/S1-2 越权 + S1-3 认证无防护**（安全底线）：组织工作区成员可越权触发付费任务、读取他人研究；任意账号可被 5 次错误密码锁定 15 分钟（DoS）、注册可无限灌水。违反"密钥、权限和用户数据不存在严重风险"门槛。
3. **A1-1/A1-2 长任务反馈缺失**（体验底线）：工具/搜索/退避期 30-60s+ 无反馈，违反"长任务具备明确反馈"与"不会长时间表现为无响应"门槛。
4. **B1-1 登录并发劣化**（容量底线）：并发 50 时登录 P50 5.2s，多用户同时登录即达卡死感。

## 条件性恢复上线（修复 P0 后）的建议路径

### 修复顺序（必须项）
1. **P0-1**：定位并修复生产构建回归（疑为 stream-stats/chat 模块循环依赖），增加生产构建冒烟 CI（Playwright 冒烟 + 构建产物自检）。
2. **S1-1/S1-2**：审批/研究接口补 actor 校验（对齐 egress_approvals.py:369 现有实现）。
3. **S1-3**：登录/注册 IP 级限流；demo 登录默认关闭（部署配置校验 env）。
4. **A1-1**：SSE 心跳（5s keep-alive/tool.running）。
5. **A1-4**：关页计费语义透明化（默认取消或明确提示后台继续）。

### 修复后可 CONDITIONAL_GO（受限上线）
- **限制用户**：个人/小团队试点（≤10 并发）。
- **限制功能**：暂不开放组织共享工作区（S1-1/S1-2 影响面）；Deep Research/沙箱/浏览器工具限制试点名单。
- **限制并发**：≤10 并发登录（B1-1 缓解线）；SQLite 单实例单进程部署（B1-7 规避）。
- **限期修复**（转 GO 前）：B1-1（登录并发）、B1-2（历史分页）、B1-3（Provider 复用）、S1-4（上传配额）、T1-1（会话幂等）。
- **监控要求**：登录 P95、SSE 断流率、内存/磁盘、模型费用日对账；部署层配置 proxy_read_timeout ≥ 120s。

### 转 GO 的额外条件
- 生产构建冒烟全绿；登录 P95<800ms（并发 10）；SSE 无 60s+ 静默；全部核心用户任务在生产构建下走通（含图谱/上传/Agent）；关键 P1/P2 关闭。
