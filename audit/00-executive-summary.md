## 最大的用户体验问题
1. **生产构建白屏**（P0）：用户打开即崩溃，无任何可用性。
2. **Agent 对话长静默**（A1-1/A1-2）：工具调用/搜索/退避期间 30s-60s+ 无反馈，用户认为系统卡死；取消为协作式，工具执行中途取消延迟=工具时长。
3. **节点选择反馈 1.7s**（U1-1）：图谱交互明显迟钝（300 节点实测，dev）。
4. **错误提示不可指导**（U1-3）：500 仅显示 "Internal Server Error 重试"。

## 最大的延迟来源（按用户感知）
1. **登录并发写锁排队**（并发时 1.4s→5.2s）。
2. **模型首 Token 之前的前置开销**：Provider 栈重建 + 双重记忆全表检索 + 历史全量加载 + 搜索串行（合计可数百 ms 至 30s+）。
3. **长会话/长 Agent 链的 O(N) 每轮重放**（历史+工具定义+转录）。
4. **SSE 无心跳导致的感知延迟**（静默期被感知为卡死）。

## 最大的稳定性风险
1. SQLite 单写者 + 30s busy_timeout：并发写时请求最坏阻塞 ~36s（B1-6）。
2. 多进程部署重复调度器/worker（B1-7）；长事务内嵌 LLM 调用（C2）。
3. 登录锁定的账号级 DoS（T1-2）。

## 最大的安全风险
1. 审批/研究越权（S1-1/S1-2）——组织共享工作区中可触发付费与泄露敏感内容。
2. 注册灌水 + 无 IP 限流（S1-3/S1-4）——存储/预算被耗尽。
3. 页面关闭后持续计费（A1-4）——费用争议面。

## 必须上线前修复
1. **P0-1 生产构建崩溃**（阻断项，无此不可上线）。
2. B1-1 登录并发（有限用户上线时可缓解，但作为限流配套必须修）。
3. S1-1/S1-2 越权（安全底线）。
4. S1-3 认证限流 + demo 默认关闭（安全底线）。
5. A1-1 SSE 心跳（长任务反馈底线，属上线门槛"长任务具备明确反馈"）。

## 可以上线后优化
- B1-2/B1-3/B1-4/B1-5（历史分页、Provider 复用、N+1、记忆检索）——数据量增长前不致命。
- F1-1/F1-2/F1-3/F1-4（分包、虚拟化）——体验优化。
- A1-3/A1-5/A1-6（Agent 工具定义/超时/退避）——成本与鲁棒性。
- T1-1（会话创建幂等）——副作用防护。
