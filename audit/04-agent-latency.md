# 04 - Agent / 模型 / 工具调用链延迟审计（Agent Latency）

> 方法：Agent 调用链代码审计（agent-chain 子智能体）+ 真实 DeepSeek 流式计时（隔离实例）。

## 1. 真实流式计时（DeepSeek，隔离实例）

| 指标 | 短问答 | 中长问答 |
|---|---|---|
| 请求→首字节 | 1.86s | 1.95s |
| 请求→首文本 delta | 1.93s | 2.00s |
| 首文本→末文本 | 0.60s | 4.43s |
| 完整响应 | 2.53s | 6.43s |
| SSE 事件数 | 63 | 370 |
| 终态 | message.completed ✅ | message.completed ✅ |

- **首 Token ≈2.0s，恰在性能预算（<2s）边缘**；SSE 传输本身健康（首字节→首文本仅 47ms，证明无整段缓冲）。
- 首 Token 前的 1.9s 包含：Provider 栈重建（B1-3）+ 历史/记忆检索（B1-2/B1-5）+ 计费预估。**搜索开启时首 Token 前最多再加 ~30s（2×15s 串行搜索，A1-2）。**
- 未测：工具调用链端到端（需 Agent 模式 + 沙箱，预算限制）→ 标记未测，代码级风险见下。

## 2. 端到端链路逐环风险（代码审计）

| 环节 | 实现 | 风险 |
|---|---|---|
| 提交→preflight | chat.py:1124 同步校验后即返 StreamingResponse | ✅ 无风险（重活延迟到 worker 线程） |
| 读会话 | _session_timeline 全量 | **B1-2 [P1] 每轮全量历史** |
| 上下文检索 | 历史全量 + 记忆双重检索 + 搜索串行 | **B1-5 [P2] + A1-2 [P2] 首 token 前静默** |
| Prompt 构建 | 全量注入（未超预算时） | **A1-3 [P1] 每轮全量转录重发** |
| 模型调用 | attempt 循环（上限 256）；60s 读超时 | A1-6 [P3] 退避固定无抖动/无整轮上限 |
| 工具选择/执行 | **每轮全量重发 ~12 组工具 schema**；串行执行；无宿主级超时 | **A1-3 [P1] + A1-5 [P2]** |
| 继续推理 | 工具结果 append 后重发全量 | 同 A1-3，随轮数二次方劣化 |
| 流式返回 | 真 SSE + 事件批量持久化（64 条/0.5s，terminal 即时刷） | **A1-1 [P1] 工具/退避期无心跳** |
| 持久化 | 消息/版本/submission 流前落库；billing 每 attempt 记账 | **A1-4 [P2] 关页后继续计费** |

## 3. 关键发现明细

- **A1-1 [P1]** 工具执行（chat.py:12332-12418）与退避 time.sleep（:12971）期间无 SSE 字节；搜索窗口最多 ~30s；nginx 60s read_timeout 会断流。建议 5s keep-alive/tool.running 事件。
- **A1-2 [P2]** message.accepted 在 stream() 内才发，搜索/上下文构建/计费预估全部前置静默。建议 preflight 后立即发 accepted + phase 事件。
- **A1-3 [P1]** 每轮全量重发工具定义（agent_runtime.py:146-211，~12 组内置）+ 全量转录（chat.py:2210-2431）。建议工具定义缓存复用 + 历史滑窗/摘要。
- **A1-4 [P2]** _detached_sse_transport 明确"客户端离开→继续 provider 迭代与计费"（chat.py:99-136）；仅显式 cancel 可停（协作式）。建议关页默认取消或明确提示后台继续。
- **A1-5 [P2]** 工具无宿主级超时；_parallel_web_research future.result() 无 timeout（agent_runtime.py:5949）。单工具悬挂即卡死整链。
- **A1-6 [P3]** retry_delays=(1,2,4,8,16) 固定无抖动、忽略 Retry-After；60s 是每次读超时非总时限（慢速流可无限占线程）。建议抖动 + Retry-After + 整轮墙钟上限。
- B1 [P1]=B1-2（历史）；B2 [中] 分支链递归重载祖先历史；B3 [✅] 记忆按任务检索 + token 预算门控（非全量注入）良好；B4 [低] 摘要为机械截断（LLM 摘要可选）；B5 [中-观察] 图片附件每次 create_stream 重跑视觉解析（ImageDescriptionCache 命中逻辑未逐行验证）。
- C1=A1-3；C2=A1-5；C3 [✅] 无重复主模型调用（幂等提交去重）；D1 [✅] 无效 API Key 秒级失败（401 不在重试集）；D2=A1-6；D3 [中] 无绝对生成期限；D4=A1-4；D5 [低] 同请求多模型均有独立用途；D6 [✅] 异常格式降级完善（json_object 回退、外挂视觉降级）。
- F1 [低-中] cancelled() 每次 DB 查询（token 密集每块一次）；F2 [低] 每次 _parallel_web_research 新建 4 线程池；F3 [低] 两查询串行可并行；F4 [✅] terminal 事件即时落库。

## 4. 结论
流式管线设计正确（真流式、幂等提交、事件批量持久化、协作式取消、错误映射完善），**但存在 4 个高风险项：①每轮全量历史+工具定义（A1-3/B1-2，二次方劣化）；②工具/退避期无心跳（A1-1，60s+ 静默断流风险）；③工具无宿主超时（A1-5）；④关页后持续计费（A1-4）**。首 Token 实测 ≈2.0s 达预算边缘，工具链启用后会进一步恶化。
