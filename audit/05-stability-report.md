# 05 - 稳定性与资源报告（Stability Report）

| 场景 | 结果 | 结论 |
|---|---|---|
| 读接口 @50 并发 | P95 <350ms，错误率 0 | ✅ 读路径稳定 |

| 吞吐 | 登录 0.2 rps @50（串行化）；读接口 4-30 rps | SQLite 单写者是登录瓶颈 |

## 4. 资源限制（实测）

| 限制 | 实测结果 | 结论 |
|---|---|---|
| 登录爆破 | 5 次错密码 → 第 6 次 429（锁定 15min） | ✅ 有保护，但**可被利用为账号 DoS（T1-2）** |
| 注册频率 | 3 连发全部 201，无任何限制 | ❌ **可灌水（S1-3）** |
| 无效 token | 401 / 14ms，会话过期语义 | ✅ |
| 缺 X-Workspace-ID | 422 字段缺失 / 即时 | ✅ |
| 大文件/配额 | 上限 20GiB 无配额（代码确认） | ⚠️ **S1-4 磁盘耗尽风险** |
| 请求队列/限流 | 无全局请求限流（仅登录账号锁） | ⚠️ 观察项 |
| 数据库连接 | SQLite 单写者；30s busy_timeout 排队 | ⚠️ B1-6 最坏 ~36s |

## 5. 长期运行与泄漏（代码审计）

- **B1-7 [P2]** 多进程部署重复调度器/worker（无互斥）→ 重复写/LLM 调用。
- C2 [中高] 长事务含 LLM 调用（memory sweep）；C3 [中] 写竞争面宽 + 0.25s 空转轮询。
- B3 [低-中] outbox embedding projection unsupported → 死信累积风险。
- R2 [低-中] 沙箱 cleanup 全表扫描；对象存储孤儿无回收。
- ✅ 正面：durable queue lease fencing、启动 reconcile、outbox 退避（2^idle 上限 60s）、沙箱容量锁 + 崩溃安全（STARTING 持久化后建容器）、scheduler 逐 workspace try/except。

## 6. 数据完整性容错（实测发现）
- **T1-3 [P3]** 单条脏数据（JSON 列格式异常）可使 GET /goals 500 并使 memory retention sweep 整批失败（实测：合成 goal 的 preferences/constraints 以字符串存储 → goals 列表 500 + sweep JSONDecodeError）。列表接口对单条坏数据应降级跳过；JSON 列读取需容错。

## 7. 结论
稳定性正面项扎实（任务持久化、崩溃恢复、内存稳定、读并发稳定）；**主要风险集中在：①登录并发写锁排队（P1）；②账号级 DoS 与注册灌水（P2）；③多进程部署重复任务（P2）；④脏数据容错缺失（P3）**。长时 soak（数小时）与多标签页并发、沙箱并发未实测（未测项）。
