## 工具参数增量预览与按需 SVG（2026-10-17）

本节描述当前源码实现；后文保留此前部署和验收记录。本次没有重启或替换正在使用的 `18000` 服务。

`tool_call_delta` 经现有 `ChatService._stream_agent_chat → rich_events` 进入有界 JSON 增量解析器。

`payload.ui_operation=ui.preview`。首份快照立即提交数据库，后续更新沿用现有事件批次。

工具最终无效时取消预览；用户中断时保留未提交标记，渲染器明确显示已接收部分。预览不能触发完成态交互动作。

显式 complete 会在资源原有总预算内收集该块的结果。若存在检索失败且缺少示意图的节点，工具返回
`ui_fallback_needed`，含当前正式 revision 和待补节点，模型可用原 patch 在同一记录按需补图后 complete。
若模型选择纯文字收尾，服务端仍可自动结束文档。成功图片不要求生成 SVG；现有 SVG 的安全校验、显示、历史兼容性保留。
工具说明与生成提示改为直接输出首段，不要求空 mount，也不要求提前规划整页或绘制备用 SVG。

## 通用富媒体回答（2026-10-16）

现有协议新增 `component=document`，通过 `upsert.blocks` 表达扁平文档树。正式聊天的极速、思考、Agent、重新生成、历史记录和 SSE 回放共用原有 `ui` Part、消息版本与 `StreamUI` 注册表。没有新增聊天入口、页面模板、模型分类请求或独立持久化系统。下文原有五类独立控件继续兼容。

节点包含稳定 `id`、可选 `parent_id`、类型、生命周期 `state` 和服务端分配的节点 `revision`。`mount/patch/complete/remove` 继续使用父块的 `base_revision` 做乐观并发校验；节点按 ID 整条替换，未涉及的节点保持顺序，删除容器级联删除后代。普通文字仍沿用既有增量 Markdown，文档中的未变化 Markdown 节点跳过重复渲染。总量限制：每条消息 20 个 UI Part，每个文档 160 节点、6 层嵌套、每层 40 个子节点，每节点正文 16000 字符；总快照仍限制为 192000 UTF-8 字节。

可组合节点：

- 内容：`paragraph/heading/list/quote/code/math/table/divider`。正文放在 `text`；列表使用 Markdown 列表语法；公式可设 `inline=true`。代码只经过现有语法高亮，不执行。
- 媒体：`image/image_group/gallery/figure/chart/diagram/graph/timeline/simulation/interactive`。
- 布局：`section/stack/row/columns/grid/media_text/tabs/accordion`。可设 `columns=1..3`、`align=start|center|end`、`width=reading|full`；具体宽度受现有消息栏约束，窄容器自动单列。布局不接受 HTML、样式字符串或事件回调。
- 图表等节点在 `visual` 中使用原来的 `props/rows/nodes/edges/items` 数据结构，并复用原注册表。嵌套图表没有强制外层卡片。
- 本地交互引擎为 `chase`（固定领先距离 10、慢者速度 1 的追赶示意）、`quadratic`（二次函数系数）、`sort_steps`（插入排序，可提供 `values`）。它们是有限的预注册计算，不能声称是任意算法/物理模拟；没有模型表达式执行或交互网络入口。

Agent 可以继续调用 `ui_stream`：

```json
{"op":"mount","block_id":"explanation","component":"document","props":{"title":"追赶问题"},"upsert":{"blocks":[{"id":"layout","type":"columns"},{"id":"p","parent_id":"layout","type":"paragraph","text":"无限细分不等于无限时间。"},{"id":"s","parent_id":"layout","type":"simulation","engine":"chase","label":"调整追赶速度"}]}}
```

后续独立 `patch` 调用可增加章节、图表数据或更新指定节点。`complete` 提交，遗漏提交时成功结束会自动完成；显式未填充的节点会变为局部错误，不会永久显示正在生成。

没有工具接口的模型可以在普通 Markdown 中穿插声明，每次只声明一小段文档：

````text
先用普通 Markdown 解释。
:::ui explanation
{"props":{"title":"追赶问题"},"upsert":{"blocks":[{"id":"s","type":"simulation","engine":"chase"}]}}
:::
继续解释与总结。
````

服务端逐字符处理任意网络切分。完整头部到达后立即创建稳定占位 Part；当前声明 JSON 闭合后验证并原位填入数据，后续文字无需等待图片。它只缓冲当前有大小上限的声明，不等待整条回答。代码围栏中的协议示例作为普通代码展示；非法 Schema、JSON、未闭合声明或仅含空布局的文档撤下占位并给出可读失败提示，不把内部 JSON/SVG 当作交付内容。上游尝试失败时撤下该次尝试的文档，重试使用新 ID，防止残留重复控件。前端在生成过程中就按照引用拆分文字，最终提交前后保持图文顺序；本地交互状态依靠消息 Part 和节点 ID 保留。

极速关闭深度思考并使用直接回答路径，保留授权资料和本节的原生图文声明。切换模式按当前轮重新确定执行能力：非智能体请求的历史投影保留正文、原生图文内容和已有文件记录，不回放历史工具事务、推理内容或不透明续接状态，也不沿用历史中的工具使用指令；原始数据库记录保持不变，切回智能体仍能重建完整历史。没有工具定义时，结构化工具事件及正文中的裸 DSML/工具调用信封在进入 SSE 与持久化之前被丢弃，绝不从文本还原执行；未生成可用文档时给出明确的未执行提示。围栏与行内代码中的协议示例继续作为文字展示。这个边界同时用于发送和重新生成，不关闭系统已授权的资料预检索或图片资源通道。

图片节点只接受 `query/alt/caption`。模型命令不能传入 `media`、URL、文件 ID 或伪造资源状态。仅在用户打开联网时，服务端按需解析工作区现有图片搜索 Provider；极速模式不依赖 Agent Runtime。检索与下载在有界线程池执行，不共享数据库 Session；每回复最多 8 次查询，全局最多 32 个在途任务。图片和来源 URL 只接受通过现有公网 DNS/域名策略的 HTTPS 地址，拒绝用户信息、非标准端口和 SVG；单个无效结果不再遮蔽后面的有效结果。

图片展示复用正式站点现有的原生文件通道。后台优先下载供应商返回的缩略图，原图作为后备候选；复用 `PublicImageDownloadClient`（从现有 `ExternalAcquisitionService` 提取的共享下载原语）的公网地址分类、固定 IP 的 HTTPS 连接、逐跳重定向校验、字节上限与真实图片解码/重新编码。单张资源最多 2 MiB，只接受静态 PNG/JPEG/WebP，继续遵守已有像素上限。工作线程只返回经过校验的字节；流式主线程重新核对节点和查询，再通过原有 `SessionWorkspaceService`、内容寻址 Blob 和 `FileRecord` 保存，检查现有工作区存储配额。SSE 只携带服务端写入的 `file_id` 与公开来源元数据，不传图片字节。

前端通过已有 `useFileStreamUrl` 获取同源、受鉴权的文件流地址，带懒加载、异步解码、固定比例占位、点击灯箱和失败替代文字。作者、许可和原始来源继续随图显示；Openverse 结果保留 creator 与 license 信息。正式站点 CSP 保持只允许同源图片，没有增加任意远程 URL 代理接口，也没有放宽鉴权或 CSP。

异步结果只更新仍存在、查询一致的原节点，并通过原 Part ID 发布 `ui.resource`；独立 `resource_revision` 避免异步图片推进模型命令的内容版本。正文生成结束最多追加 2 秒资源等待窗口，未就绪图片降级，不无限阻塞回答。搜索 Provider 自身超时上限为 8 秒，检索/下载任务共用约 8.75 秒截止时间，资源轮询上限为 9 秒；已发出的搜索请求不能强制中止，但迟到结果不会写入已结束消息或保存为文件。没有配置、联网关闭、检索/校验失败时显示替代文字，不虚构图片。

每个节点有局部错误边界；旧的纯 Markdown、公式、代码、工具记录和独立图表保持原通道。图片结果文字只作为数据展示。预览 `/rich-response-preview.html` 使用正式消息分组和渲染组件，左右是同视口代码重建对照，流式节奏为本地回放。正式功能仍从现有聊天界面进入。

## 模型指令

每次调用必须是一个完整的 JSON 对象；前端不解析尚未闭合的 JSON。数据增量发生在多次独立工具调用之间，不是在单次工具参数的 token 流内部。工具名为 `ui_stream`。

```json
{"op":"mount","block_id":"activity","component":"chart","props":{"title":"项目活跃度","columns":[{"key":"commits","label":"提交量"}],"source_note":"虚构示例数据"}}
```

挂载时 revision=0，可以没有数据。接着填充记录：

```json
{"op":"patch","block_id":"activity","base_revision":0,"upsert":{"rows":[{"id":"jan","label":"1月","values":{"commits":38}}]}}
```

```json
{"op":"patch","block_id":"activity","base_revision":1,"upsert":{"rows":[{"id":"feb","label":"2月","values":{"commits":55}}]}}
```

```json
{"op":"complete","block_id":"activity","base_revision":2}
```

`mount` 创建稳定消息 Part，`patch`、`complete`、`remove` 替换同一 Part 的快照，保持原始排版位置。revision 每次加一。工具返回最新版本和 `[[artifact:block_id:activity]]`，模型可将引用放进最终回答指定位置，并支持 `|layout=block/inline/side`。没有显式引用时沿用已有的叙述邻接排版规则。

`upsert` 按记录 ID **整条替换**，保留未提及记录，不是字段级深合并；`props` 按顶层字段合并后重新验证。`delete` 例如 `{"rows":["jan"]}`。删除图节点会同步删除关联边。边必须引用同一次更新后存在的节点。`complete` 后不允许继续修改，允许 `remove`；同一回复里的多轮工具调用可以持续更新未完成控件。跨回复修改旧消息不在本版范围内。

## 组件目录

- `chart`：`props.columns=[{key,label}]`，`chart_type=line|bar`，`rows=[{id,label,values:{key:number}}]`。本地切换图形、指标、最近 5/10 项，悬停和键盘查看数值。缺失值保留间断，支持负数。
- `graph`：`nodes=[{id,label,description?,group?}]`，`edges=[{id,source,target,label?}]`。本地拖动、缩放、查询、选择和关联详情；明确点击解释按钮才调用 Agent。
- `timeline`：`items=[{id,label,date?,description?,value?}]`，本地展开详情。
- `table`：`props.columns=[{key,label}]`，`rows=[{id,label,values:{key:scalar}}]`。本地筛选和数字/文字排序。
- `metric`：`items=[{id,label,value,description?}]`。

共有属性：`title`、`description`、`unit`、`source_note`。真实数据应注明来源；虚构样例应明确标记。组件样式由产品主题决定，没有 HTML、JavaScript、任意样式或表达式入口。

## 传输与恢复

SSE envelope 仍携带 `message_id`、`message_version_id`、递增 `sequence` 和持久化事件 `id`。`payload.ui_operation` 是 `ui.mount/patch/complete/remove`；`payload.part.type=ui`；`payload.part.data.protocol=suip/0.1`。传输采用 `part.started` 和 `part.replaced`，携带经过验证的完整组件快照，避免客户端丢失一条 patch 后继续使用错误状态。

模型输入是小批量的记录增量；当前 SSE 每次发送完整快照，适合中小型图表。上限：每回复 20 个控件，每控件 192000 UTF-8 字节、500 行、100 节点、300 边、100 项、12 列。大规模图谱需要分页或另外的画布，不应无限向消息流堆数据。

重放使用现有 `GET /api/v1/sessions/{session_id}/messages/{message_id}/events` 和消息快照接口。历史列表保留 UI 数据，刷新即可恢复最终数据与混排位置；本地筛选和拖动位置不持久化。模型成功结束而忘记 `complete` 时运行时自动完成；取消/失败时显示已生成数据和中断状态。重试创建新消息版本，旧版本控件不能发送交互动作。

最终回答可能把控件从流式位置移动到正文引用处。同一页面内使用有上限的 Part ID 状态缓存保留图形类型、筛选、节点选择和拖动位置，页面刷新后恢复默认选择。

## 图库失败自动降级为 SVG（2026-10-17）

降级融合在现有 image/image_group/gallery 资源节点中。模型提出图库查询时，同时画出与主体和本题重点相符的 `fallback_svg`；新图片命令缺少它会返回可修正的校验错误。图库正常时只显示照片；无结果、检索/下载失败、超时、未配置或文件加载失败时，在原节点显示 SVG。沿用模型给出的 parent_id、分组与列数，前端只负责适应可用宽度。

用户改为要求 Openverse 失败时自动降级 SVG。本轮沿用正式聊天现有资源流和渲染器：新图片查询先由模型提供同主题的安全静态 SVG，后端异步尝试真实图片；最终无结果、限流、超时、下载或存储失败时发布 unavailable，原位置自动展示已备 SVG；浏览器图片加载或文件票据失败也自动切换。成功的真实照片保留。无需用户重新生成或另发“画图”指令，也不需要失败后再调用一次模型。

初步怀疑“后续 patch 漏带 SVG 会清空”经验证并不准确：既有 Command 校验实际会拒绝缺 SVG 的图片查询。新增回归在修改前确认，同主题省略 SVG 的 patch 被拒绝，以及异步合并不能恢复已遗漏的备选图。本轮修复为：
