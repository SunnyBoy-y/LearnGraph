# 聊天表情包

表情包复用 LearnGraph 的 Provider、计费、持久化后台任务、消息部分、SSE 和历史回放。没有 Embedding 模型时，中文关键词检索仍可使用；素材不会因模型切换而失效。

## 使用入口

- 设置 → 对话与学习 → 表情包：搜索、导入、编辑私有素材、启停表情包、查看索引进度。
- 同一页面的“表情市场”：分类搜索、整包预览、一键添加、下载 ZIP。已添加的包可直接返回“我的表情”管理。
- 聊天输入框的表情按钮：搜索并发送内置或本人导入的贴纸。
- 智能体模式：按需调用 `search_stickers`，允许弃权，选择后通过 `send_sticker` 输出原生消息部分。每个回复版本最多一张。
- 极速模式不开放新的工具。用户发送的贴纸仍可展示、保存并以简短语义进入历史；标准 Unicode Emoji 沿用现有文本渲染。

关闭“AI 主动使用表情包”或将回答风格中的表情设为禁用，会阻止主动检索与发送；用户手动选择不受该 AI 开关影响。

## 内置素材

内置 `Fluent · 日常回应` 包包含 12 张精选 Microsoft Fluent Emoji 3D 素材，并附中文名称、关键词、表达意图、使用和不适用场景。无需下载模型即可使用。

- 原始仓库：<https://github.com/microsoft/fluentui-emoji>
- 固定修订：`1ffb34c752ecf5d402f04cfb4b392c77f57c54bc`
- 原图未修改；中文语义由 LearnGraph 整理。
- 图片及许可原文位于 `backend/app/assets/stickers/`；`LICENSE` 中保留 Microsoft 的 MIT 许可声明。

素材属于应用分发内容，Docker 的 `COPY backend/app ./app` 会一并包含。用户导入的原图、封面和语义存在工作区数据库中，随数据库备份保存，不依赖临时上传目录。

## 授权素材市场与下载

当前为经过核验的精选目录，不是上游完整商店：Fluent 三套共 24 张、Noto 一套 24 张、OpenMoji 一套 24 张，共 5 套、72 张原图。三个来源无需 API Key 或厂商逐应用审批，仍须遵守素材许可。市场定义位于 `backend/app/assets/stickers/market.json`，每张记录上游文件路径、固定提交、作者与 SHA-256，预览、安装、下载前检查内容完整性。所有素材随应用分发，运行时不访问第三方下载地址，不接受客户端自定义源 URL。前端支持按来源筛选。

- Fluent：MIT，保留 Microsoft 完整许可。
- Noto：仅分发 PNG 图片资源，Apache-2.0，完整许可与 Google 上游声明分别保留；不包含采用 OFL 的字体。
- OpenMoji：CC BY-SA 4.0，逐张作者取自固定版本官方元数据，保留署名、来源、许可链接与未修改声明；聊天消息附可见署名链接。若改编图片，须遵守该许可的改编及相同方式共享条件。

仓库根目录 `THIRD_PARTY_NOTICES.md` 说明素材与应用代码的许可边界；应用根 MIT 不替代上述素材许可。

市场包附有人工整理的中文语义卡（含配字、标签、意图、适用与禁用场景）。安装复用安全导入流程，重复安装幂等；新增市场包归本人管理，不会自动发布到公共空间。安装后关键词立即可用，已配置 Embedding 时由原有后台管线增量构建索引。

市场卡片和详情支持“移除”，通过 `DELETE /stickers/market/{id}/install` 从当前用户的表情库中隐藏整包；内置包也可个人移除，不影响其他成员。移除后不再显示在个人库、选择器或 AI 检索中，也不能通过旧 ID 新发送；保留原图、历史消息取图、许可和索引缓存。市场仍可预览与下载，重新添加恢复原包和语义，不产生重复图片。个人移除与工作区管理员停用不同；重新添加不能覆盖管理员对内置包的停用。已停用的个人包重新添加会恢复启用。

下载 ZIP 包含原图、可再次导入的 `manifest.json`、完整对应的 `LICENSE.txt` 和带来源、作者、逐张路径与哈希的 `NOTICE.txt`。导入再导出也会保留这两份文件；用户提供的来源声明作为未核实的来源信息保存，不因上传而变成已授权公共素材。已安装的私有包也可以导出，需验证工作区和所有者；停用包仍允许所有者导出备份，但不再参与搜索与聊天取图。私有导出不是公开再分发授权。市场不抓取微信表情商店，不把 Signal 等目录的软件开源等同于其中素材获准再分发；新增来源应先逐包核验许可、版本及声明。

## AI 可读语义管线

统一流程为：原图 / 动图 → 清单或文件名关键词 → 可选视觉分析 → 经校验的语义 JSON → 关键词索引 → 可选 Embedding 索引 → 既有 Agent 工具、消息部分和历史。无视觉模型仍能使用市场语义卡或手工描述；无 Embedding 仍能关键词检索。

“AI 可读语义管线”复用平台任务配置中的视觉 Provider，不绑定模型。默认不发送私有图片。用户可逐包点击“补全语义”并确认，或明确同意“自动分析我的新导入表情”；授权按工作区和用户保存，不由管理员替其他用户开启。自动模式也会处理本人历史导入中缺少描述的表情；视觉模型稍后配置后，后台协调会继续调度。已有描述（包括人工修订和市场标注）不会自动重写。

视觉任务复用 `DurableJob`，类型 `sticker.semantic`，每张素材一个有去重键的任务，失败最多尝试三次并可手动重试。GIF/APNG/WebP 动图最多采样首、中、尾三帧，缩放至 512px；这是有界采样，不保证理解全部动作。图中文字只作为不可信数据，模型不获得工具；输出限制大小，并通过严格 JSON schema 校验描述、OCR、情绪、交际意图及使用边界。模型可能误读，用户仍应检查并修正。

调用前经过平台预算预检，调用后记录 `sticker_vision` 用量。网络等待期间不持有写事务。保存前检查租约令牌和有效期、模型目标、原图哈希、语义版本；任务期间发生人工编辑或取消，不覆盖新内容。成功会触发原有增量 Embedding 索引协调；失败保留原图与关键词，不返回 Provider 可能含敏感内容的原始错误。关闭自动分析会取消自动排队 / 执行中的租约，已发送的请求不可撤回；单次明确授权的手动任务独立于自动开关。

自动分析和自动索引要求启用原有 `LEARNGRAPH_DURABLE_QUEUE_ENABLED`。多进程可共享数据库队列，无需另建服务或安装固定模型权重。

聊天选择器与管理网格中，未描述的素材显示原图及“待分析 · 点击识别”。点击先打开单张分析确认，不直接发送、不分析整包；确认后后台执行，弹窗轮询显示语义结果和失败重试。模型未配置时可手工填写描述，或明确选择仅发送原图。已描述的普通表情保持点击即发送。蓝色纯色验收夹具不是图片加载失败，不应作为默认表情提供；预览验收数据与应用内置素材隔离。

## 用户导入

支持多张 PNG、JPEG、WebP、GIF、APNG，或单独一个 ZIP。不再将 100 张和 24 MiB 作为导入限制；导入原始文件及 ZIP 展开内容复用系统 `max_upload_bytes` 安全上限（默认 512 MiB，可由部署调整），单文件仍不超过 4 MiB，每批最多处理 1000 张以防资源耗尽。图片尺寸、动画帧数及累计解码像素也有上限。SVG、可执行文件、不安全 ZIP 路径与符号链接不会作为素材导入。接口直接处理已落盘的上传流，ZIP 逐张解码校验，待入库原图与封面暂存临时文件，不把整包图片重复堆在内存中；临时文件在成功或失败后关闭。

导入默认为本人私有：列表、搜索、发送和图片下载都检查工作区与所有者。工作区管理员仍可全局停用内置包；个人库开关只影响当前用户，普通成员也可停用自己的内置包。重复导入相同文件集合会返回已有包。

## 启用上限与排序

每位用户最多同时启用 100 张图片，不是 100 套，也不是导入数量上限。按本人保存的表情包顺序、再按包内原始入库顺序取前 100 张；关闭的包不占名额，边界包可部分启用，其余图片继续保留。界面显示整库启用数、每包实际启用数和等待名额状态。拖动手柄（鼠标与触摸）或聚焦手柄按上下方向键可排序；通过 `PUT /stickers/library/order` 持久保存，通过 `PUT /stickers/library/packs/{id}` 修改个人开关。排序和开关不影响其他成员，也不删除原图或历史消息。

聊天选择器、关键词和向量检索及新消息发送共用同一份有效图片列表，不能通过旧图片 ID 绕过上限。搜索空串按个人包顺序返回。共享向量索引只对各所有者当前有效图片的并集及默认内置图片构建；排序或开关后，新增有效图片交由原有增量索引管线处理，旧向量可缓存但不会绕过个人过滤。视觉自动分析只排队当前有效图片，任务开始前再次检查，以免对超额或已停用的图片调用模型。

ZIP 可附 UTF-8 `manifest.json`，`file` 相对于清单所在目录：

```json
{
  "name": "我的反应表情",
  "license": "填写素材实际来源及许可；私有导入不代表获得公开分发授权",
  "stickers": [
    {
      "file": "smirk.png",
      "name": "被识破了",
      "description": "熟人间表达被识破后的心虚和小得意",
      "ocr": "嘿嘿",
      "tags": ["心虚", "被抓包", "小得意"],
      "emotion": ["得意"],
      "intent": ["友好调侃"],
      "use_when": ["熟悉对话中的轻松玩笑"],
      "avoid_when": ["正式道歉", "严肃悲伤"],
      "standalone": true
    }
  ]
}
```

没有清单时，文件名作为初始名称与关键词，界面标记“待补充描述”。点击私有表情可编辑中文描述、关键词和不适用场景。该流程不要求视觉模型，也不自动把图片发送给视觉服务。

启用远程 Embedding 后，表情的正向描述及本轮检索意图会发送给所选 Provider；原图和完整图库不会进入该调用。配字及导入清单始终作为数据处理。

## 模型绑定与自动索引

默认跟随平台任务模型配置中的 Embedding Provider 与模型，独立于长期记忆功能本身的启停。若尚未分配任务模型，且恰好只有一个已启用、具有默认模型的专用 Embedding Provider，可自动采用它；多个候选不会任意选择第一个。

也可选择独立 Provider 与模型，或仅关键词模式。实现不导入或安装任何指定的 Embedding 权重，复用现有兼容接口与 Ollama 适配器。

Profile 记录 Provider、端点身份哈希、模型、部署修订、请求维度、查询/文档指令、预处理及适配器版本、度量与归一化约定。通过稳定 JSON 序列化计算指纹，不包含 API Key。实际输出维度单独锁定，后续批次与查询检查向量数量、维度、有限数值和非零范数。

可选 Provider capabilities：`embedding_dimensions`、`embedding_model_revision`、`embedding_query_instruction`、`embedding_document_instruction`。这些参数属于服务端适配配置；本地模型的池化由其推理服务负责。供应商同名模型静默升级无法可靠自动感知，可更新部署修订或使用“重建索引”。

任务模型保存会触发协调；持久化队列还在启动及运行期间约每 15 秒重新协调已保存配置，覆盖 Provider 新增、启停和修改。需要启用应用原有的 `LEARNGRAPH_DURABLE_QUEUE_ENABLED`。

索引构建使用独立 generation：

1. 可靠记录目标与任务，分批处理，每批最多 10 个素材。
2. 网络请求前释放数据库写事务，复用现有计费和预算检查。
3. 持久化向量和内容哈希；进程重启后通过队列租约恢复。
4. 校验目标配置、任务租约及当前素材版本，持续追平期间的导入与编辑。
5. 完整后通过条件更新切换活动 generation，过期任务不得覆盖新目标。

新增或修改素材时，复用同 Profile 下未变化的向量，在新 generation 中只补充变化项。原活动索引保持可用。失败不覆盖活动索引；修复 Provider 配置后可重新调度失败任务，也可手动重建。重建进行时，仅在仍可精确调用旧 Profile 时使用旧向量；否则回退关键词。

关键词与向量通过排名融合，无跨模型统一相似度阈值。负向场景不混入正向向量；工具返回少量简短候选，最终由聊天模型结合语境决定是否发送。停用素材会即时退出候选和下载范围。非活动、非目标的旧索引在保留 7 天后清理。

## 消息与兼容性

`sticker` 沿用既有 `MessagePart` 外层结构，`data` 保存 `sticker_id`、`pack_id`、内容哈希版本、替代文本与简短含义。服务端解析资源，模型不生成图片地址。

用户手动发送和智能体发送均保存为真实消息部分，经既有事件序列流出并参与历史、重试和版本管理。纯贴纸回复允许没有正文；历史模型投影补充简短语义，极速模式仍排除工具执行状态。Web 与 Android 的共享消息渲染链路展示同一组件，资源不可访问时显示替代文本。动图支持静态封面及系统减少动态效果偏好。

## API

- `GET /api/v1/stickers`：本人可见包与索引状态。
- `GET /api/v1/stickers/search?q=...&pack_id=...&offset=0&limit=24`：默认关键词搜索；可显式请求 `semantic=true`。
- `POST /api/v1/stickers/import`：multipart `files`，可选 `name`。
- `PUT /api/v1/stickers/{id}`：编辑本人素材名称与 `semantics`。
- `PUT /api/v1/stickers/packs/{id}`：设置 `enabled`。
- `GET /api/v1/stickers/{id}/content?poster=true`：经过授权的图片或静态封面。
- `PUT /api/v1/stickers/settings`：管理员设置 `mode`、`provider_id`、`model_id`、`ai_enabled`。
- `POST /api/v1/stickers/rebuild`：管理员请求全量重建，返回 202。
- `GET /api/v1/stickers/market?q=...`：授权精选目录、安装状态和预览清单。
- `GET /api/v1/stickers/market/{id}/preview/{index}`：带认证的市场预览。
- `GET /api/v1/stickers/market/{id}/download`：含图片、语义与完整许可的 ZIP。
- `POST /api/v1/stickers/market/{id}/install`：一键安装到本人表情库。
- `GET /api/v1/stickers/packs/{id}/download`：经过所有者授权的已安装包导出。
- `GET/PUT /api/v1/stickers/pipeline`：本人视觉管线状态与自动分析授权。
- `POST /api/v1/stickers/packs/{id}/analyze`：请求体 `{ "consent": true }`，分析本人缺少描述的启用素材，返回 202。
- `GET /api/v1/stickers/{id}`：经过权限检查的单张素材与当前语义。
- `POST /api/v1/stickers/{id}/analyze`：请求体 `{ "consent": true }`，仅分析当前素材，返回 202。

所有端点使用现有 Bearer 与 `X-Workspace-ID` 工作区认证。

## 验证

后端测试覆盖无模型关键词、私有权限、ZIP 校验、语义编辑、模型/修订切换、构建中配置变化与素材导入、失败回退、维度检查，以及真实 Agent Runtime → SSE → 持久化 → 历史链路的纯贴纸和文字加贴纸。

前端测试覆盖检索模式保存、文件导入、语义编辑、失败状态和聊天选择器，结合消息分组与既有设置迁移测试。浏览器验收应使用隔离数据库，检查实际图片加载、导入、搜索、编辑、聊天发送与刷新回放；本地测试模型验证的是协议与链路，不代表真实模型的语境选择质量。
