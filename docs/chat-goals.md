# `/goal` 长程任务

在普通聊天输入框选择「+ → 长程任务」，或直接输入 `/goal 目标`。目标最好写明要交付什么、如何验收，以及哪些限制需要遵守。

```text
/goal --rounds 8 整理本会话的研究资料，交付中文对比报告；至少对比三份来源，逐条列出出处，并把无法验证的结论单独标明。
```

| 命令 | 行为 |
| --- | --- |
| `/goal 目标` | 在当前会话启动长程任务；默认最多 6 轮。 |
| `/goal --rounds N 目标` | 自定义轮次上限（1–20），不等同于时间、Token 或费用上限。 |
| `/goal` 或 `/goal status` | 查看当前会话的任务状态、轮数和最近进度。 |
| `/goal pause` | 尚未执行时立即暂停，执行中则在本轮结束后暂停。 |
| `/goal resume` | 发起人可继续暂停、受阻或失败的任务，仍受原来的剩余轮次约束。需要补充资料时，可先在会话中发送信息再继续。 |
| `/goal clear` | 清除任务状态，不删除消息、文件或已完成的操作。如果正在执行，等待本轮结束后清除。 |

同一会话同时只有一个目标，需要先清除旧任务才能新建。关掉浏览器不会停止执行；后端必须启用持久队列（`LEARNGRAPH_DURABLE_QUEUE_ENABLED`，默认开启），发起时需选择支持工具调用的远程模型。命令仅接收文本，可引用会话中已有资料；网络搜索沿用启动时的联网设置。与「设定学习目标」和定时任务相互独立。

## 执行语义

- Worker 每次租约执行最多一轮，通过现有聊天服务保存消息和工具记录。每轮会重新检查发起人的会话权限，不扩大现有工具、沙箱或出网权限。
- 一轮正常结束后，系统用同一模型发起一次不使用工具的结构化验收请求，依据目标、上轮检查点和本轮可见证据判断继续、完成或受阻。验收也受工作区用量与计费规则约束；模型判断不是外部人工审计。
- 检查点和下一轮调度一起提交。服务重启后的恢复按队列租约进行：已完成并持久化的回复可以重新验收；中断的轮次不自动重新运行工具，用户可查看已有记录后决定是否继续。
- 到达轮次上限但未验收通过，会显示「轮次已用尽」，而不是「已完成」。暂停和清除不撤销本轮已做的操作。
