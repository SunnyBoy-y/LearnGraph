# 记忆污染防护

记忆的证据 ID 只能证明来源存在，不能证明模型结论受原文支持。模型自报的高置信度不再足以自动提交新事实。

## 写入约束

- 创建、修改、草稿提交以及 v2 记忆事件使用同一危险内容检查，拦截凭证、角色边界伪造及常见注入指令。检查覆盖标题和正文。
- 后台抽取返回 `source_quote`。提交时重新核验所有证据的工作区、作者、资格、删除状态，以及原始消息角色、状态、所属会话和内容哈希；不再悄悄丢弃伪造证据 ID 后使用剩余 ID 提交。
- 自动入库的事实必须与完整用户陈述可逐字核对；只允许保守的人称和格式规范化。引文、代码、文档、假设、问题和临时任务陈述不能充当自动个人事实证据。
- 原文支持不了的改写或推断保留为待确认草稿。显式记忆编辑同样检查新事实是否受本次用户输入支持。
- 自动提交的标题从有证据的事实产生，防止正文合法、标题编造。人工确认另外生成用户确认凭据，不冒充原模型已经获得支持。

这是有意保守的准入策略。非逐字的概括、翻译及部分表达方式可能需要人工确认。正则与原文比对不是通用语义蕴涵证明，也不能保证识别所有注入变体。

## 召回约束

旧召回、混合检索及用户摘要都重新检查危险内容和来源。明确不可信的作者、已撤销的证据、已改变的原始消息等不进入自动上下文。检索投影与当前正文不一致时也不会注入过期内容。

模型派生记忆在 ContextBuilder 中保留 `derived` 信任标签，不再因为检索目标类型是 `memory` 就一律升级成 `user_explicit`。

## 防止历史经历改变新需求

- `usage_policy` 区分事实、任务经历、明确偏好和未确认假设。自动抽取的任务经历进入 Session，标为 historical，不进入全局画像。推断的偏好不能自动提交。
- 普通“做个动画”不会注入历史赛车、烹饪或音乐题材偏好。明确要求“按我的喜好”才允许题材建议；当前指定的主题及排除条件仍然优先。
- 简洁讲解、字幕等纯呈现偏好可以调整表达，不能改变主题和功能；混合了题材的偏好不能冒充纯呈现规则。
- 重要性、同工作区和置信度不再代替相关性。无关候选可以全部排除，弱语义相似度不足以准入。任务、Episode 和策略等辅助上下文也检查适用性，防止旁路。
- 原始消息和用户确认才是偏好证据。召回次数不会再增加旧召回评分中的记忆强度。旧的偏好声明若找不到用户偏好证据，不能用于自动个性化或当前画像。
- ContextBuilder/Router 的策略版本已递增，避免复用旧策略下的上下文身份。

## 批量抽取及资源控制

默认累计 10 个新用户轮次或空闲 900 秒再抽取。显式记住/纠正/忘记、任务边界及会话关闭立即触发；手动强制抽取保留即时执行。

事件队列以 Session 的持久化抽取游标合并任务，未执行的任务可以延后；已领取的任务不会被后续消息覆盖。工作线程和定时恢复扫描共用 readiness 检查，活跃短批次不请求模型，也不消耗重试次数。生成期间到达的新消息会安排后续批次，避免只依赖下一次聊天唤醒。

抽取是增量的：只有上次成功推进游标之后的用户消息会进入下一批。模型返回的 `has_more` 只是兼容字段，不能控制服务端重读同一批证据；服务端按已完成消息和长消息偏移量推进游标。长消息按最多 7,000 字符的片段处理，每个片段拥有自己的检查点，因此后续片段不会再次发送前缀，并为提示词和已有记忆保留输入预算。

每个已发出的模型请求都在持久化作业中留下输入批次收据。收到结构化结果后，结果会先保存，再执行本地草稿写入；本地写入失败时恢复过程复用该结果，不再次调用模型。若请求超时、进程崩溃或传输失败，无法知道远端是否已计费，作业会标记为 `model_outcome_unknown` 并停止自动重发。配置变更不能重开这种已发出请求的重试窗口；仅未发送请求的预检或提供商配置失败可以重新尝试。

这是一项有意的 at-most-once 取舍：在通用提供商没有可验证幂等键的前提下，无法同时保证“远端只收费一次”和“未知结果一定不丢”。未知结果需要人工确认后，才可在手动抽取接口上显式传入 `retry_unknown=true` 重新发送；普通强制抽取不会重发。新消息在正常成功的游标之后继续增量抽取。

新增适用性检查不调用模型；节省的具体 token 和账单仍取决于对话分布、上下文长度及定价。相关性和偏好识别采用保守规则，部分表达可能暂时不触发个性化，不等同于完整语义理解。

新记录的准入版本为 `provenance.admission_version=1`。旧格式记录缺少逐字证明属于待审线索，不直接当成错误事实，也不会因此批量删除或屏蔽；仍执行可信来源和危险内容检查。人工确认或编辑会生成独立证据，允许纠正误判。

## 只读存量审计

在 backend 目录运行：

```powershell
.\.venv\Scripts\python.exe -m scripts.audit_memory_contamination
```

命令使用数据库只读模式，仅输出数量和原因，不打印原文、用户标识或凭证，不删除或修改记忆。`review_candidates` 包含旧格式证据不足的候选，`would_block_on_recall` 才是新召回防护会排除的数量。审计结果不代表修复代码已经部署。
