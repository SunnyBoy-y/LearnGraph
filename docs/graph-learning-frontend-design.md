# 图谱学习节点：前端设计方案

日期：2026-09-17。依据当前学习页、交互桥接、API 类型及全局样式进行静态检查。本次交付是设计方案与可交互样稿，不修改业务实现，不代表后端运行验证通过。

## 检查结论

现有实现已经具备教材、交互实验、试卷、异步构建与成就展示的功能骨架。下一版应从“功能集中在一个页面”推进到“每种学习行为都有清晰的空间、反馈和下一步”。保留项目现有黑白主题，金色专用于有效的通关成就。

1. **教材需要更强的阅读层次。** `frontend/src/features/learning/node-learning.css` 第 6 行把目录、正文、图解组合为基础双栏；正文为 15px / 1.95，与全局阅读字号 16px / 1.75 不一致。图解集中在正文前方，应围绕相关概念就近呈现；跨章节图文定位需要内容结构支持。
2. **实验已经可操作，但缺少任务引导。** `learning-activity-scene.tsx` 已有动作白名单、消息来源校验及服务端确认机制，应保留。界面应明确当前目标、状态变化、动作结果，以及场景加载失败时的文字操作入口。当前 480px 场景高度在移动端仍可能过大。
3. **试卷需要独立的考试视觉。** `node-learning-page.tsx` 已支持多种题型、答案保存和交卷；目前题目、进度与结果主要是顺序排列。建议增加题型分组、答题导航、持久保存状态，以及提交前的未答题清单。
4. **后台准备需要可理解的状态。** 当前设置包含开关、范围和任务操作，但任务标题、失败恢复及已有内容更新时的进度不够突出。已有教材时也应显示新版本准备状态，保留可用旧版。
5. **成就应区分有效通关与历史记录。** 当前已有过期成就数据。只有当前版本有效通关使用金边；内容变更后保留历史分数，但标记“内容已更新，待重新挑战”。阅读完成、实验完成与测评通关不能混为一种状态。

## 信息架构与页面设计

### 1. 图谱入口与学习路径

节点仍在现有图谱中。点击知识、实验、测评节点分别打开对应默认视图。节点同时表达三层信息：类型图标与名称；内容状态（未准备、准备中、就绪、失败）；个人进度（未开始、学习中、已完成、已通关）。不以颜色作为唯一识别手段。

进入学习页后保留工作区顶部导航。左侧展示当前路径及当前位置；主区承载教材、实验或试卷。桌面侧栏 200–220px，主区自适应，阅读内容最大宽度沿用 760px。样稿使用三个关联节点解释路径，真实产品应区分“切换节点”与“同一节点切换内容标签”，保留各自 URL 与进度。

### 2. 教材页

从上到下：节点类型与路径 → 标题和学习目标 → 章节导航 → 正文与图解 → 要点总结 → 随堂检查 → 本节完成及下一步。正文使用共享阅读变量，默认 16px，行高 1.75–1.85；正文不再塞入仪表盘式卡片。

图解放在相关解释之后，包含图题、说明和可访问文本。复杂图允许展开。交互卡用明确边界嵌入正文，普通段落留白分节。导师入口应携带节点和当前章节上下文；未接入章节上下文前只标注“询问当前节点”，不声称理解选区。

### 3. 实验工作台

顶部呈现目标和完成条件；中心为 SVG / HTML / 子应用场景；下方呈现操作控件、最近反馈及可展开记录。练习模式提供即时纠错，正式测评模式不泄露答案或隐藏评分规则。

动作点击后显示“提交中”，服务端确认后更新场景及记录；失败保留原状态并允许重试。加载失败时显示“场景暂不可用，切换文字操作”，不能只留空白 iframe。重置仅重置本次练习，正式考试按独立规则执行。

不把任意生成的 HTML 直接作为可信评分器。沿用现有沙箱及宿主动作协议；成绩、成功判定与奖励由服务端确认。只有 API 给出允许动作及原因时才禁用操作并显示理由，前端不能自行推断业务规则。

### 4. 考卷与结果

考前显示题型构成、总分、通过条件、关键题要求、是否包含实践及保存方式。当前 API 无时间限制字段，因此不设计真实倒计时。作答界面以纸张结构分题型，题号导航区分未答、已答、当前题。

自动保存显示“保存中 / 已保存 / 保存失败”；失败提示常驻并支持重试。交卷前列出未答题，明确提交动作；提交中防重复。提交后展示总分、通过情况、关键条件与逐题解释。实践卡只显示服务端可公开的反馈。

通过时节点出现 2px 金边、成就图标与“已通关”，不反复播放奖励动画。未通过使用中性结果页，重点给出需要复习的内容。重试不抹除历史通关。错题跳转精确章节需新增题目与章节映射，当前可先回到节点教材。

### 5. 内容准备面板

全局入口固定命名“内容准备”，显示进行中数量；正式设计为桌面右侧抽屉、移动端全屏面板。内联样稿为便于同时比较页面，采用可展开面板呈现相同信息。

首屏包含自动准备开关、当前路径 / 全部合格新节点范围、插图开关；紧邻开关说明：仅对开启后新增且未被提问的节点生效，已提问节点不进入自动预构建。保存中、成功和失败均应明确；开关关闭后的在途任务处理必须与实际后端策略一致。

任务行展示节点名称、当前阶段、阶段进度和操作。生产管线对用户显示：学习规划 → 教材与图解 → 实验规则 → 交互场景 → 测评 → 可选插图 → 发布。可选插图未启用时标记跳过，不伪造耗时、费用或完成百分比。阶段 4 / 7 是阶段进度，不等价于总时间完成 57%。

失败保留阶段和可理解的原因，并按 API 能力提供重试、取消；已提问节点明确标记跳过原因。旧内容可用而新版本构建中时，允许继续阅读，不能显示为首次构建空页。

## 必须覆盖的状态

- 学习页：加载、无内容、准备中、首次失败、就绪、旧版可用且更新中、内容过期、无访问权限。
- 教材：未开始、阅读中、完成、插图不可用、进度保存失败。
- 实验：场景加载、可操作、动作提交、状态冲突、动作失败、目标达成、文字替代模式。
- 测评：未开始、恢复作答、保存中、保存失败、未答确认、提交中、已通过、未通过、历史成绩过期。
- 准备面板：设置保存中 / 失败、空队列、排队、各阶段运行、成功、失败、取消、资格跳过。

## 视觉与响应式规范

沿用全局黑白主题变量，不新增全站品牌色。页面用浅灰底与白色内容面，在深色模式映射为深灰底与较亮内容面。边框使用现有 border token；通关金色单独配置亮暗主题。错误、警告沿用既有语义色并配文字。

标题 28px，移动端 24px；正文 16px；辅助文字 12–13px。间距采用 4 / 8 / 12 / 16 / 24 / 32；普通控件圆角 8px、内容面 12px。每个操作区只保留一个高强调主按钮。

1024px 以上保留侧边路径；768–1023px 收窄侧栏，实验说明与场景按空间折行；小于 768px 路径改为顶部折叠或换行导航、正文单栏；320px 仍应无横向溢出。场景使用内容响应尺寸，不把桌面固定高度直接下放。

键盘可完成全部操作；正文图有替代说明；状态更新使用适量 aria-live；控件触达区域至少 44px；考卷分组使用 fieldset / legend。不能仅通过金色、悬浮提示或动效传达通关；尊重减少动画设置。

## 组件划分与落地边界

建议将现有大页面拆分为 `NodeLearningShell`、`LearningPathNav`、`LessonReader`、`LearningTaskChecklist`、`ActivityWorkbench`、`ExamPaper`、`AnswerNavigator`、`AttemptResult`、`BuildPreparationPanel` 和 `NodeAchievementBadge`。复用项目 Button、Dialog、Markdown、主题变量及现有 `LearningActivityScene`，避免再建立一套 UI 基础库。

**可直接基于现有 API 改进：** 页面布局、阅读样式、标签 URL 同步、题型分组、答题导航、保存失败呈现、构建阶段列表、现有结果和过期标识、场景失败替代界面。路径和节点名优先复用已有图谱数据。

**需要接口补充或明确约定：** 图文与章节关联、题目到知识点 / 章节的映射、允许动作及禁用原因、正式时间限制、跨节点先修解锁规则。若当前上下文没有图谱节点名称映射，构建列表应补充 node_title 或批量解析接口。预计时长、真实成本、自动生成质量分数不可凭空展示。

**生产验收：** 知识→实验→测评路径可完整走通；刷新恢复状态；失败重试不重复计分；成绩由服务端返回；旧版成就不冒充当前通关；无内容与已有旧版的构建提示均正确；320 / 768 / 1280px 与深色主题可读；键盘完成一次练习及考试。

## 本次样稿范围

样稿可切换教材、实验、试卷与准备面板；实验包含顺序反馈及重置；试卷包含必答校验、评分、通关装饰及重试。全部数据为本地示例，简化烹饪场景仅用于说明交互，不是实际烹饪教程。样稿未覆盖所有正式题型与异常分支，这些以本方案的状态清单作为业务实现验收范围。未连接后台，也未重新运行此前被阻止的后端测试。
