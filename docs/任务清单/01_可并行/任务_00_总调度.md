# 总调度窗口

> 多窗口并发时的总控面板。**先读本文件再开工**；每完成一个任务，回来在本文件末尾的「进度日志」追加一行。
> 本文件交给「调度方（通常是你）」，各执行窗口不必写它，只需要写自己的任务文件。

## 一个关键规则：query-key 小工具是共享基石

`frontend/src/lib/query-keys.ts`（和它的清理队友 `auth-query-cache.ts`）是几乎所有可并行/不可并行任务
都会遇到的**小文件**。它们没有脏文件锁，所以：

- 多个窗口**同时** import 同一个工具函数没问题，但**谁想在文件里加内容**就得串行，先后落盘；
- 因此 P0-A（唯一需要写 query-keys.ts 的任务）建议排在可并行波次里，并优先提交，
  之后 everyone 都 `import { workspaceQueryKey }` 现有实现即可，**不用再改这个文件**。

## 默认不可并行的主因（识别冲突源）

这几个文件体积大、职责杂，几乎一定会互相覆盖，必须单窗口：

- `frontend/src/features/chat/chat-pages.tsx`
- `frontend/src/features/graph/graph-pages.tsx`
- `frontend/src/components/layout/workspace-shell.tsx`

只要有两个任务同时写它们，就必然冲突。因此 02_不可并行 里只放有序推进的单窗口任务。
