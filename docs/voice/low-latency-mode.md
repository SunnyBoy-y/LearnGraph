# 全双工语音：低延迟模式

语音模式的模型选择器菜单内提供“低延迟模式”开关，默认关闭。开启后，复杂请求可先听到
“嗯……我来分析一下。”等短应声，再继续得到实际回答。

## 行为

- 使用现有 `VoiceResponseFeedback → journal → TTS → generation gate → playback ledger`
  路径；不增加额外模型请求或独立音频播放器。
- 从模型响应开始留出 350 ms 宽限：正式文本先到时跳过应声。350 ms 是排程宽限，
  不是保证的用户听音延迟；TTS 和网络仍有各自耗时。
- 分析、比较、资料研究、计划生成、代码排查等请求使用短的类别对应应声。
  识别是确定性规则，未宣称覆盖所有复杂任务。
- 普通短问答、问候、原样复述、静默控制和后台结果主动播报不额外应声。
- 每个持久轮次至多应声一次；工具续轮和并行调用不会重复触发。
- 新输入、打断、正式回答开始或关闭开关会取消尚未发出的应声。
  正在播放的音频仍由现有打断机制处理。
- 模型收到提示：应声由系统处理，直接生成实际内容，避免再次添加受理开场。

## 配置与持久化

创建语音会话时可传 `low_latency_mode: true | false`；省略时保留已有会话偏好，
新会话默认关闭。通话中可调用：

```http
PATCH /api/v1/voice/sessions/{voice_session_id}/preferences
Content-Type: application/json

{"low_latency_mode": true}
```

接口沿用会话所有者、工作区及写权限检查；仅接受布尔值。偏好存入已有的
`context_snapshot`，不增加数据库列。普通上下文刷新保留该偏好。

变更发出 `context.updated`（`reason=voice_preferences`），运行中的 watchdog 更新
会话策略并撤销旧计时器。这条路径不替换 LLM 对话历史，不重指模型，不提升会话代次。
应声开关面向后续响应生效。

浏览器沿用 `learngraph.voice.preferences.v1`，与思考等级合并保存。显式本地选择
优先；没有本地选择时恢复服务端会话偏好。保存失败保留原值，并允许重试；
切换会话或挂断后忽略旧请求的迟到结果。

## 验证边界

测试覆盖开关默认值、创建与热更新、刷新恢复、所有权、严格布尔输入、复杂/简单请求、
真实计时器发出应声、每轮幂等、提前回答、打断、新输入、关闭取消、原样复述、
后台结果排除，以及先前修复的多轮上下文保留。

前端提供真实开关组件的独立交互预览：
`/previews/voice-low-latency/index.html`。预览中的响应文字是示例，不发起真实语音。

源码回归、构建及浏览器预览均不能代替部署后的 WebRTC、物理麦克风和 TTS 供应商验收。
